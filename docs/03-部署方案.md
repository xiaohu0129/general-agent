# 03-部署方案（Docker Compose 单机）

> 形态：**单实例**后端 + Nginx 托管前端 + **外部 MySQL** + **真实 LLM**，HTTP 访问。
> 适用：中小规模（单 uvicorn 进程，asyncio 可承载数百并发 SSE 长连接）。
> 多实例高可用需引入 Redis 并补实现 Redis 版登录态（当前 `LoginSessionStore` 仅内存实现），见文末。

## 一、架构

```
浏览器 ──HTTP──> Nginx 容器(:8080 -> 容器:80)
                  ├── /  静态资源 front/dist（SPA，try_files 回退 index.html）
                  ├── /chat、/stream      -> backend:9093（SSE：关缓冲、长超时）
                  └── /auth、/sessions、/health、/internal -> backend:9093
                        │
                        ├── 外部 MySQL（用户/会话/消息三表，惰性自建）
                        └── 外部 LLM（OpenAI 兼容，POST {base_url}/v1/chat/completions）
```

- 后端单进程承载内存 `Broker`（SSE 扇出/续传）与内存登录态（Cookie+Session），**不要开多 worker/多副本**。
- 前端经 Nginx 同源访问后端，cookie 为第一方，`SameSite=Lax` 正常工作；开发态的 Vite 代理不再需要。

## 二、目录与文件

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 后端镜像（python:3.12-slim，pip 安装本包，运行 `python -m general_agent`） |
| `deploy/Dockerfile.frontend` | 前端多阶段镜像（node:20 构建 → nginx:1.27 托管） |
| `deploy/nginx/default.conf` | Nginx：SPA + SSE/API 反代 |
| `docker-compose.yml` | 编排 backend + frontend，环境变量注入 |
| `.env.example` | 环境变量模板（复制为 `.env` 填写） |
| `.dockerignore` | 后端构建排除 .venv/tests/front 等 |

## 三、部署步骤

```bash
# 1. 准备外部 MySQL：建库（表会由服务惰性自建，库需先存在）
#    mysql> CREATE DATABASE general_agent CHARACTER SET utf8mb4;
#    并确保账号对该库有 ALL PRIVILEGES；服务能从容器网络访问到 MySQL。

# 2. 配置环境变量
cp .env.example .env
#   编辑 .env：LLM_BASE_URL / LLM_API_KEY / LLM_MODEL、MYSQL_HOST/PORT/USER/PASSWORD/DATABASE
#   - MySQL 在宿主机：MYSQL_HOST=host.docker.internal（compose 已加 host-gateway 映射）
#   - MySQL 为远程实例：填其 IP/域名
#   - LLM_BASE_URL 不要带 /v1 后缀（代码自动拼 /v1/chat/completions）

# 3. 构建并启动
docker compose up -d --build

# 4. 验证
curl http://localhost:8080/health        # 经 Nginx 代理，返回 status:ok
# 浏览器打开 http://<主机IP>:8080 ，注册 -> 登录 -> 对话
```

日志：`docker compose logs -f backend`；停止：`docker compose down`。

## 四、关键配置说明

- **SSE 反代**（`deploy/nginx/default.conf`）：`/chat`、`/stream` 必须 `proxy_buffering off`、
  `proxy_http_version 1.1`、清空 `Connection`、`proxy_read_timeout 3600s`（长于 broker 心跳 15s），
  否则流式输出会被缓冲或长连接被代理掐断。
- **登录 cookie**：当前 HTTP，`AGENT_SECURITY__SESSION__COOKIE_SECURE=false`；
  上 HTTPS 后必须改 `true`（cookie 仅经 TLS 传输）。
- **CORS**：同源经 Nginx 访问时浏览器不发跨域请求；若用其他源（如直接访问后端端口、另一域名）访问，
  需把该源加入 `AGENT_SECURITY__CORS_ORIGINS`（JSON 数组）。session 模式禁止 `["*"]`。
- **配置覆盖优先级**：环境变量 > .env > config.yaml > 默认值。compose 中用 `AGENT_` 前缀 + `__`
  表示嵌套（如 `AGENT_MYSQL__HOST`、`AGENT_SECURITY__SESSION__TTL_HOURS`）。
- **观测**：compose 默认 `AGENT_OBSERVABILITY__ENABLED=false`（避免无 OTLP 端点时报错/噪音）；
  需要接入时再配 `AGENT_OBSERVABILITY__OTLP__ENDPOINT`。

## 五、运维与边界

- **单实例约束**：`uvicorn` 单进程；不要 `--workers >1`，不要起多个 backend 副本——
  内存 Broker/登录态不跨进程共享，会导致 `/stream` 收不到事件、登录态不共享；
  **大工具产物（blob）也存于本地 `artifacts/` 目录**，同样不跨实例共享，多副本会下载不到他人产物。
- **数据持久化**：业务数据（用户/会话/消息元数据）在外部 MySQL；超大工具结果/胖产物外置到
  本地 blob 目录（`artifacts/`，compose 已挂载命名卷 `agent-artifacts` 到 `/app/artifacts`），
  容器重建不丢产物；消息行内只存 head 摘要 + `content_ref` 引用。登录态在内存，后端重启后用户需重新登录。
- **备份**：备份 MySQL 的 `agent_user` / `agent_chat_session` / `agent_message` 三表；
  如需保留历史工具产物，一并备份 `artifacts/` 卷（产物可由业务侧重生成，非权威事实源）。
- **升级**：`git pull && docker compose up -d --build`；表结构变更靠 `CREATE TABLE IF NOT EXISTS`
  惰性建表（当前未上线，`agent_message` 新增 `content_ref/content_size/content_kind` 三列可 drop 表重建；
  上线后新增列需自行迁移，当前无 migration 工具）。

## 六、后续：上 HTTPS / 多实例

- **HTTPS（有域名后）**：Nginx 加 443 server + 证书（certbot 或挂载自有证书），
  80 跳 443，compose 映射 443，并把 `AGENT_SECURITY__SESSION__COOKIE_SECURE` 置 `true`。
- **多实例高可用**：部署 Redis（compose 加 redis 服务或外部），设置 `AGENT_REDIS__URL` 启用
  `redis_broker`；**还需补实现 Redis 版 `LoginSessionStore`**（接口已预留 create/get/touch/revoke），
  然后 backend 可扩多副本，Nginx  upstream 配多个后端。
